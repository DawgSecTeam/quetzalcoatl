5. autofirewall.sh - set -e with Firewall Script
   File: autofirewall.sh:2
   `set -e` causes the script to abort on any iptables command failure.
   If a command fails mid-script (e.g., missing module, wrong syntax),
   the firewall is left in a partially-flushed state with no protection.
   Fix: Remove `set -e` and check return codes explicitly, or add
   a trap to restore rules on failure.

6. harden.sh - Race Condition: All Shells Locked Before bluey Exists
   File: harden.sh:19,23
   Line 19 sets every user's shell to /bin/false, including root.
   Line 23 creates the bluey user with /bin/sh AFTER all shells are locked.
   If the script fails between lines 19-23, the system is unrecoverable via SSH.
   Additionally, line 29 `rm -rf /home/bluey/.*` matches `.` and `..`.
   Fix: Create bluey before modifying /etc/passwd. Use `find` with
   `-not -name '.' -not -name '..'` instead of `rm -rf /home/bluey/.*`.

7. harden.sh - No Validation of Hashed Password Arg (blank bluey password) [NEW]

   The lock loop (line 68) only touches UID<1000 users, so bluey (UID>=1000)

   Also misleading: line 45 says "Setting password for root & bluey" but
   root's password is never set - root is only locked via `!` in the loop.

12. funcs/detectOS.sh - bash-only `&>` under /bin/sh (always reports "rhel") [NEW]
    File: funcs/detectOS.sh:3-11
    Every `command -v <pm> &> /dev/null` uses the non-POSIX `&>` redirection.
    On dash (Debian/Ubuntu /bin/sh), `cmd &> file` parses as `cmd &`
    (background) plus a stray `> file`, so the if-condition sees a background
    job that always succeeds - detectOS always echoes "rhel" regardless of OS.
    sh -n passes because the syntax is valid-but-misinterpreted.
    Fix: Replace `&>` with `>/dev/null 2>&1`.

15. Logging exec Can Fail Silently
    Files: baseline/standard.sh:24-25, baseline/specific.sh:16-17
    `exec sh -c "\"$0\" $* 2>&1 | tee \"$LOGFILE\""`
    `$*` is unquoted - arguments with spaces will break word splitting.
    If /var/tmp/.log/ does not exist (race with activate.sh), the exec
    replaces the shell with a failing process and the script dies.
    Fix: Quote `$@` properly. Ensure the log directory exists before exec.

16. chmod 777 on Log Directory
    File: activate.sh:18
    `chmod 777 /var/tmp/.log` makes the log directory world-writable.
    Any local user can create, modify, or delete log files, or create
    symlinks for arbitrary file writes.
    Fix: Use `chmod 700` or `chmod 755` with appropriate ownership.
